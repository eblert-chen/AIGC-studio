# 平台管理员控制面 v1

## 边界

- 平台管理员独立于任何公司的老板、组长和运营角色。
- 浏览器只调用客户平台。渠道凭据、账号池、路由和故障切换仍只属于中转站。
- 平台管理员可以创建、启停公司，为公司充值，管理模型目录和公司价格，以及配置公司级权益。
- 普通公司成员不能调用平台管理员接口，也不能自行提升公司级权益。

## 可扩展权益目录

模型使用独立的模型目录。其余权益统一使用资源目录，并通过 `kind` 分类：

| kind | 含义 | 示例 |
| --- | --- | --- |
| `feature` | 平台功能 | 视频复刻、一键生成带货视频 |
| `agent` | 智能体 | 选品智能体、脚本智能体 |
| `external_api` | 对外 API 产品 | 统一生成 API、批量任务 API |

资源名称和数量不写死在前端。新增功能或智能体时，平台管理员创建一条目录定义；所有公司权益矩阵会自动包含它，未授权时默认关闭。

目录项可修改显示名称、说明和启用状态，稳定的 `key` 和 `kind` 不允许漂移。停用目录项不会删除历史授权，但公司使用时必须失效。

## 公司权益矩阵

`GET /api/v1/platform-admin/companies/{company_id}/entitlements` 返回该公司的完整模型和资源目录，包括尚未授权、已关闭和目录已停用的项目。

- 没有授权记录时，`grant_id` 为 `null` 且 `enabled` 为 `false`。
- 模型授权保存该公司的整数分单价及限制型能力覆盖。
- 功能、智能体和外部 API 逐项保存开关及可选配置。
- 启用已下线模型或已停用资源必须失败。
- 公司停用后，新的公司请求立即失败，但目录和历史账务仍保留。已经创建、预占或送入中转站的任务继续按原状态机结算、释放或进入对账，停用不冒充批量取消。

## 充值、收入与成本

四个财务口径必须分开：

1. `platform_recharge_cents`：公司充值流水总额，表示资金流入，不等于已确认收入。
2. `platform_income_cents`：成功生成任务的客户结算流水总额。
3. `channel_cost_cents`：已录入并对账的真实渠道成本总额。
4. `gross_profit_cents`：客户结算收入减去渠道成本。

渠道成本使用独立的只追加账本 `channel_cost_entries`。每条记录包含稳定幂等键、渠道标识、渠道类型、金额、发生时间和外部凭证，可选关联公司、平台任务和中转站任务，并记录首写来源 `platform_admin` 或 `relay` 及管理员操作者。相同幂等键和完全相同业务载荷返回原记录，任意业务字段不同返回冲突；跨管理员与 Relay 入口重放不会改写首写来源和操作者。

成本记录禁止 UPDATE、DELETE 和 PostgreSQL TRUNCATE。需要冲正时只能追加一条有明确凭证的新记录，不修改历史。

平台不从客户售价推测渠道成本。成功任务没有关联的真实成本记录时，看板返回 `channel_cost_status=incomplete` 和未对账任务数量；明确零成本也必须写入金额为 0 的对账记录。失败任务不自动产生客户收入或渠道成本。如果上游实际收取了失败费用，应依据真实账单显式写入成本账本。

## 管理员看板

看板按公司展示：

- 公司状态和可用、预留余额
- 充值和成功结算消费
- 调用总量、成功量、失败量和成功率

平台汇总展示：

- 公司总数和启用公司数
- 调用总量、成功量和失败量
- 充值、收入、渠道成本和毛利
- 各渠道类型和渠道标识的成本拆分
- 未完成渠道成本对账的成功任务数量

消费明细继续支持公司、员工、模型、状态和时间筛选。渠道成本明细支持公司、任务、渠道和时间筛选。

## 接口与集成边界

- 企业完整权益：`GET /api/v1/platform-admin/companies/{company_id}/entitlements`
- 资源目录新增/查询/更新：`POST|GET /api/v1/platform-admin/resources`、`PUT /api/v1/platform-admin/resources/{resource_id}`
- 企业资源授权：`PUT /api/v1/platform-admin/companies/{company_id}/resources/{resource_id}`
- 渠道成本录入/查询：`POST|GET /api/v1/platform-admin/channel-costs`
- Relay 成本同步：`POST /internal/channel-costs`，只接受内部服务凭据
- 平台总览：`GET /api/v1/platform-admin/dashboard`

当前管理员充值是不可变账本上的人工调账，不等同于支付订单、签名回调或支付对账。Relay 成本同步入口已经可用，但只有接入真实供应商账单并由 Relay 主动上报后，渠道成本和毛利才具备生产财务含义。

`external_api` 当前表示可扩展的公司级授权产品。它完成了目录、逐公司开关和默认拒绝控制面，但不自动生成客户 API key；正式对外 API 仍需补齐密钥签发与轮换、配额、限流、调用审计和用量计量，并在每条服务端路由消费对应资源 key。

## 默认拒绝原则

- 新目录项默认不授权任何公司。
- 缺失授权、关闭授权、停用目录、停用公司全部拒绝使用。
- 模型声明的 `required_resource_keys` 在任务创建前逐项校验，并写入任务能力快照。
- 后续新增的非生成业务路由必须在服务端消费对应资源 key，页面隐藏不能替代鉴权。
